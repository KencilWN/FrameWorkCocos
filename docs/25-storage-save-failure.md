# 实验二十五：保存失败时，内存与存档会怎样

2026-10-22，D03，K2进行中。实验二十四保存/读取/显示职责修正已完成，类型检查通过；原版已有跨重开日志，本轮基线一起回归修正版。暂估10～15分钟，学习者修改临时实验代码，完成后恢复，助手不代写业务实现。

## 本轮契约

当前规则是领取成功即修改内存并刷新UI；保存报告失败时输出错误，保留本次内存修改。停止重开只能恢复上次成功保存的状态。这是本Demo选定的离线教学策略；当前没有“保存失败后撤销领取”的实现。

本轮模拟LocalStorage.setItem返回false，验证调用方如何处理；不制造真实平台异常，不据此声称LocalStorage.catch、权限或磁盘故障已经验证。

## 完整操作

1. 保持真实保存调用，在InventoryMain正常领取一次药水，停止重开确认数量保留，把此时药水数量记为N，再停止。这一步回归上一轮修改并建立已保存基线。
2. 在InventoryPanel.saveItems中，将实际storage.setItem调用暂时替换为const bSccess = false。保留已有if(!bSccess)错误提示。原调用可先注释，便于恢复。不要保留原调用后才把结果改成false，那样实际上已经写入，不是本实验。
3. 预览，点击一次药水。预期有“保存失败”提示，UI仍显示N+2；内存已经增加，存档没有改动。
4. 停止重开，预期显示N。此时仍是模拟失败版，但loadItems/refreshItems不会写入，能读取旧基线。
5. 恢复真实setItem调用并保存脚本。重新预览，领取一次→N+2；停止重开仍N+2，证明真实保存恢复。本轮结束不得遗留false注入。

需要临时替换的实际代码形状：

```ts
// 临时实验：本次不调用真实写入，模拟它返回失败。
const bSccess = false;
```
