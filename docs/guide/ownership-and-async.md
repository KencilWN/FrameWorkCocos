# 状态、资源与异步的所有权

“所有权”在本工程中指：谁创建/持有对象，谁允许修改，谁决定结束，谁执行清理。它是设计责任，不是JavaScript提供的自动借用检查。

## 状态先归类

| 内容 | 当前负责人 | 结束/共享方式 |
| --- | --- | --- |
| 商店余额与背包 | ShopModel | 页面当前独立持有；多页共享需另设玩家状态负责人 |
| 购买数量1/3 | ShopPanel | 临时页面选择，重开默认，不放资产快照 |
| 商品名称/价格 | ItemConfig | 静态定义，背包只存ID/数量 |
| 存档文本 | LocalStorage工具读写，页面决定key | 浏览器/设备本地，不由Git同步 |
| 商品格子的回调 | 创建它的页面提供 | 格子复用时应替换/清掉旧业务引用 |
| 资源引用 | ResourceScope | 每次成功load持有一份，消费者结束后dispose归还 |

当前ShopModel恢复通过替换钱包/背包完成，因为没有把内部对象交给别处长期持有。如果未来Owner、面板、服务都保存旧Wallet引用，替换this.wallet不会更新那些引用；需要重新设计通知或共享状态入口。

## 监听的活动期与实例期

面板隐藏时还存在，但不应继续响应可见期的按钮/状态通知，使用activeScope；实例整个存活期间要保留的能力使用lifetime。DisposableScope只记录清理动作，不猜应该清理哪个资源。

原EventDispatcher是同步通知，不是状态容器。晚订阅不会自动拿到历史数据，所以onEnable通常先订阅、再主动读取当前状态刷新。只有一个页面时直接刷新简单且合理；多个消费者出现后再比较事件/ObservableValue的收益。

## 异步结果可能已过期

场景：选择A开始慢请求，随后选择B开始快请求。若每个完成回调都更新Label，后到的A可能覆盖B。LatestRequest每次begin返回新票号，完成后仅当前票号可应用；隐藏时invalidate使旧票号失效。

票号判断不取消请求，也不释放请求得到的资产。网络若支持取消要单独接入；ResourceScope在关闭后收到资产会平衡addRef/decRef并reject。已经resolve但await尚未继续的结果，也必须检查票号/节点有效性，不能认为Promise成功就永远可用。

所有Promise调用都要有失败归宿：await+catch，或调用方catch。序列队列close阻止未开始任务，运行中的工作仍会继续；不能让“取消”的名字掩盖实际行为。

## 资源与节点不是同一物

Prefab资源是模板，instantiate创建Node实例。销毁Node不等于拥有者所有资源引用自动都归还；把对象放进池也不是释放，池仍保留节点和它引用的内容。

ResourceScope只管理自己增加的资源引用，不调用全局releaseAsset强行释放其他人可能使用的资源。两个scope加载同一资产，各自addRef；关闭一个只归还它的一份。

正确结束顺序是先停止使用/清空组件引用或实际销毁消费者，再释放拥有的资产。Node.destroy通常延迟到本帧适当时机，不要在请求destroy后立即认定所有消费者已结束。可在对应Node销毁事件或更长生命周期持有者中归还；真实引擎释放效果需要Creator验证。

对Sprite，可以先设置spriteFrame=null，再dispose该次加载scope；对Audio，必须考虑音效仍在播放。AudioPlayer.stop只处理音乐source，playOneShot并不受它统一停止，不能立刻释放短音效资源。

## 性能与解耦分别判断

- 接口/类型的编译约束不自动改善运行性能；减少隐式全局依赖改善的是可理解性和替换范围。
- snapshot复制和JSON序列化有O(n)工作与分配，不放update里无理由执行。
- ObservableValue是浅层显式替换，没有深遍历，但对象原地修改不会通知，也不会防止外部修改。
- PrefabPool减少反复instantiate/destroy，却会保留内存并增加重置规则；三个静态格子通常无需池。
- 原版资源缓存/深观察/虚拟列表功能更多，依赖和故障范围也更广；先用具体需求比较，而非默认越复杂越先进。

每个新模块至少回答：收益是什么？新增的状态/成本是什么？失败/关闭时谁清理？什么时候应换更复杂方案？
