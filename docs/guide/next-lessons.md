# 后续实操路线与验收

2026-11-02工程独立化后，代码备齐不等于课程完成。每个新主题先按[四行方法](problem-solving.md)分析，再由学习者实现接入、运行与解释；此页只给需求和检查，不提前生成业务答案。

## 立即继续：数量选择（K3收尾）

按[实验32](../32-shop-quantity-selector.md)：界面切换1/3、显示当前数量，切换不改资产不保存；按钮使用点击当时数量。价格明确标单价，重开数量1但资产恢复。当前源码仍buyNum=2，尚未实施。

验收临时独立key首次30/空 → 多次切换不改资产 → 3瓶药水0/potion3 → 重开0/potion3且数量1 → 不足拒绝。恢复原key。需要亲手绑定新增节点并解释选择归页面、交易规则归模型的理由。

## 下一组：异步有效期（K4，约2～3次实操）

目标：选A慢、选B快，最后显示B；关闭后旧回调不能更新重开的界面；失败有提示且不挂起。

第一轮先用自己的可控Promise模拟，不碰资源；理解await期间对象会变化。第二轮自行使用LatestRequest比较直接完成就刷新。第三轮关闭/重开与失败组合，说明“忽略结果”和“取消工作”的区别。

验收A后到不覆盖B、关闭期间到达不应用、新一轮仍可成功、reject有归宿。记录实际输出，而非只读模块源码。

## 资源加载与持有（K5，约3～5次实操）

在本工程自行准备一个resources内的小Prefab/图像，不使用工作素材。阅读本地原版ResourceLoader的load/destroy和缓存入口，再用ResourceScope完成一次加载。

分别验证：正确路径、错误路径、加载前关闭、两处共享同一资源关闭一处不破坏另一处、消费者实际销毁/清空后归还引用。列出Node实例、Prefab资产、SpriteFrame和scope的负责人。Node替身计数通过只能辅助定位，实际释放/显示仍在Creator观察。

## 组件基类与页面（K5～K6，约2～4次实操）

先将一个小组件改用ScopedComponent，比较手写on/off与scope；不要一次重构所有旧课。解释覆盖生命周期为什么需要super，验证重复显隐不累加。

用PanelHost打开自己新建的奖励弹窗，root显式传入；关闭只销毁自己节点，其他UI不受影响。Prefab资源由谁保留要独立说明。原MgrLayer/PrefabComponent读本仓库快照，对比删减功能和API差异。

## 状态通知与第二使用场景（K6～K7，约2～4次实操）

新增奖励入口复用Inventory规则，但不能调用购买方法冒充领奖。重新决定玩家状态负责人，使两个页面真的操作同一份资产。

选一个简单页面对比手工事件与ObservableValue；分别试原地修改和替换。读原ViewModel/JsonOb，说明浅/深观察的收益与开销，不因为模块存在就给全部业务套观察器。

## 选修：池、列表、队列、音频

- 池：从3个商品扩展到较多数据，先观察instantiate数量；再使用PrefabPool复用，验证数据/回调/选中状态不会串条目。虚拟列表原版在阅读包，不强制本轮整体移植。
- 队列：两个任务一个失败，验证后续推进；close后未开始任务不执行，已开始任务不能凭名字假装停止。若顺序await已足够，允许不引入队列。
- 音频：自己准备有权使用的短音频，绑定AudioSource、验证用户手势播放/音量/音乐停止；说明one-shot与音乐停止边界，clip什么时候能释放。

## 独立交付（K7～K8）

做一个1～2小时小需求，先提交分析，再独立实现；给出依赖边界、失败处理和实际回归。新建第二个试水项目按[复用清单](../framework/reuse.md)只带需要的模块，说明哪些不带及理由。

完成一次Web构建：在Creator构建面板选择Web目标和学习场景，构建到已忽略的build目录，在实际浏览器运行。记录构建结果和浏览器运行；不能把typecheck或Node测试当Web通过。引擎/平台阻碍要记录首个错误与待验项。

## 阶段和时间如何动态调整

原4～6学习周核心、6～8周强化窗口保留为预算基线，按每天6小时/每周5天。停学只顺延日历，不填完成天数。现在增加独立推导训练，分析、编码、排错分别记录；2～3个实际学习日复盘一次，再调整资源/异步预算和选修范围。

验收维度：能运行、能解释原因与代价、能自己改、能处理反例。AI主体实现只计辅助，不因文件已齐跳过独立接入。
