# 实验十三：独立定位一次漏绑引用

前置：target与has对照已通过，正常清零和三次显隐回归已有用户反馈。当前正常绑定时计数器可运行。本轮预计5～10分钟，先减少到需求与排查范围提示，由学习者自己修复onLoad。

## 1. 制造单一故障

停止预览，在编辑状态下清空CoinCounterL组件的buyButton属性，保留购买按钮节点。右侧引用保留原样，保存场景后重新运行。

记录自定义的漏绑提示，以及随后第一条异常及所在方法/行。不以看到红字就笼统判断为之前target问题，结合报错字段和Inspector空引用定位。

## 2. 修复目标

- 左侧缺少必要引用时，错误提示包含节点名和需要绑定的buyButton字段，便于定位。
- 该组件停止后续初始化，不继续产生额外空引用异常。
- 右侧仍能独立运行。
- 正常绑定时，初始化、按钮、金币通知和显隐行为保持。

只调整CoinCounter的onLoad中相关处理，方法体由学习者完成。先查看当前绑定检查之后的语句是否仍执行；不通过给缺失按钮临时new一个对象来掩盖漏绑，也不删除报错日志。

## 3. 修复后保留故障复测

暂时保持左buyButton未绑定，保存代码并重新运行，确认只出现明确的绑定提示，无额外空引用异常；右侧10→购买0应正常。

## 4. 恢复正常场景

停止预览，将左侧自己的购买Button组件重新拖回buyButton字段，保存场景，再运行。左侧初始100，购买一次70；右侧正常，控制台无本轮漏绑提示或异常。

反馈修复前第一条后续异常、修改的onLoad及故障/恢复两次结果。可以直接让助手读取已保存源码，但运行现象由用户反馈。不要把故障场景留作后续正常起点。

## 教学审阅依据
