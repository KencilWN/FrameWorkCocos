# 实验三十二：让玩家选择购买数量

布置：2026-10-26，K3收尾中的页面整合练习。上一轮指定数量模型的金额/不足/模拟入包失败退款已定向通过；Creator多件操作尚未确认。本轮预计25～40分钟，尚无实际用时。主要实现在学习者，聊天提供完整需求，本文只归档。

## 需求与约束

InventoryMain的ShopMain新增一个切换数量按钮与数量Label：初始每次买1件，点击在1/3之间切换，显示“每次购买：N件”。切换不购买、不保存、不改变金币/背包。现有商品按钮按点击当时选择的数量购买，商品价格明确标注为单价。购买成功沿用完整快照保存，失败不写。数量选择是页面临时状态，不增加到Shopsnapshot；重开恢复默认1，资产按存档恢复。

## 设计任务

先写目标、成功/失败状态、反例和执行顺序四行，再自行实现，无需等教师逐条给代码。说明为什么数量选择由ShopPanel持有、每个ItemCell是否需要再持有数量。当前回调最终读取this.buyNum，可直接使用点击当时数量；对比在创建时保存一份数量副本可能造成切换后仍用旧值。ShopModel接收quantity并验证业务，不必记录页面选择；ItemCell继续显示商品/报告点击。商品单价变化与数量切换不需要重建Prefab列表。

## 实施提示

ShopPanel.buyNum初始1；新增Button/Label序列化引用并绑定、纳入onLoad必要引用检查。用onEnable/onDisable注册/撤销同一个切换回调，参考现有ItemCell；首次显示与每次切换都同步数量Label。ItemCell.setData中价格文字标注单价即可，不要求新增字段、继承、事件或接口。切换可直接更新Label，不必调用刷新全部资产/重建列表；本轮性能关注避免不必要的实例化和写盘，不声称两个数字操作需要性能优化。

## 运行验证

验证时将商店key临时改为framework-demo.shop.quantity-check.v1，以独立记录避免旧0余额干扰；不删除或覆盖原key。新key首次30/空。多次切换1/3不改变资产；选3买药水后0/potion3；停止重开，仍0/potion3且数量回到1；再选3买药水失败，资产不变。结束后恢复framework-demo.shop.snapshot.v1，回到原记录。不要通过反复注入默认状态覆盖保存来准备测试。反馈四行分析、操作结果和用时，不预填实现/运行通过。
